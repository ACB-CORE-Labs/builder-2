# External tooling

builder-II should orchestrate best-in-class engineering tools instead of recreating them.

The integration rule is simple: third-party tools must improve codebase mapping, context engineering, prompt evaluation, git workflow, static analysis, or knowledge capture. They should be optional until a builder-II command depends on them.

## Tool detection

Inspect the registry:

```bash
uv run builder-tools list
uv run builder-tools check
uv run builder-tools check --tier tier1
uv run builder-tools check --tier tier2
uv run builder-tools check --tier notes
uv run builder-tools missing
```

## Tool installation

Use the installer script for local setup:

```bash
bash scripts/install-tools.sh status
bash scripts/install-tools.sh required
bash scripts/install-tools.sh tier1
bash scripts/install-tools.sh tier2
bash scripts/install-tools.sh notes
bash scripts/install-tools.sh all
```

Modes:

| Mode | Installs |
| --- | --- |
| `required` | Required tools only: `repomix`, `semgrep`, `ruff`, `ripgrep`, `tea`. |
| `tier1` | Required tools plus `fd`, `pyright`, `pre-commit`. Serena remains `uvx` on demand. |
| `tier2` | Optional tools: `ast-grep`, `aider-chat`, `promptfoo`. |
| `notes` | Optional open-source note UIs: Logseq and Zettlr. |
| `all` | Tier 1, Tier 2, and notes tools. |
| `status` | Print current PATH status without installing. |

The default installer mode is `required`. It intentionally does not install optional note-taking UIs, Aider, promptfoo, or ast-grep unless you ask for those modes.

## Tier 1 tools

These are the highest-leverage tools for the local agent/developer platform.

| Tool | Purpose | builder-II integration |
| --- | --- | --- |
| `repomix` | Pack repository files into AI-friendly context files. | `context-pack` / repo packaging. |
| `serena` | Semantic code retrieval and MCP-style code intelligence. | Start read-only: symbol map, references, diagnostics. |
| `semgrep` | Static/structural policy scanning. | Target-scoped invariant and policy scans. |
| `ruff` | Python lint/format quality gate. | Quality preflight. |
| `pyright` | Python type checking. | Type preflight. |
| `pre-commit` | Git hook orchestration. | Install lint/type/scan/test hooks. |
| `rg` | Fast text search. | Repo map and task-scoped context selection. |
| `fd` | Fast file discovery. | Repo map and context selection. |
| `tea` | Forgejo/Gitea CLI. | PR, issue, and release workflows against this repo's private Forgejo host. |

## Tier 2 tools

These are valuable after the Tier 1 registry and context-pack path are stable.

| Tool | Purpose | builder-II integration |
| --- | --- | --- |
| `aider` | AI pair-programming reference implementation. | Benchmark/reference lane, not a default replacement for Goose. |
| `ast-grep` | AST-based search/rewrite preview. | Structural search and codemod planning. |
| `promptfoo` | Prompt/agent evals and red-team tests. | Lane-guide/persona prompt regression tests. |

## Notes and knowledge capture

The default notes backend is not Obsidian. The default is a plain Markdown vault generated by builder-II.

Recommended internal shape:

```text
.builder/notes/
  index.md
  sessions/
  decisions/
  recipes/
  tool-runs/
  handoffs/
```

Why Markdown-first:

- no application lock-in;
- easy git diffs;
- works with Obsidian, Logseq, Zettlr, Foam, VS Code, or plain terminal tools;
- easy for approved tools and operators to read and write;
- easy to pack into context with Repomix.

Optional UIs:

| UI | Open source | Role |
| --- | --- | --- |
| Logseq | Yes | Graph/outliner UI over Markdown/org notes. |
| Zettlr | Yes | Minimal Markdown writing and Zettelkasten-style notes. |
| Foam | Yes | VS Code-based Markdown knowledge base. |
| Obsidian | No | Optional proprietary Markdown vault UI; not a core dependency. |

For builder-II, the important integration boundary is the Markdown folder, not the editor.

## Install hints

```bash
brew install repomix semgrep ruff ripgrep fd tea ast-grep
uv tool install pre-commit
npm install -g pyright promptfoo
uv tool install aider-chat
```

Serena should begin as a read-only semantic integration and should not be allowed to edit files until a dedicated smoke test proves safety.

## Near-term implementation order

1. `builder-tools` — detect installed/missing Tier 1/Tier 2 tools.
2. `builder context-pack` — use Repomix to build AI-ready packs.
3. `builder preflight` — run git status, ruff, pyright, semgrep, and recipe checks.
4. `builder notes` — create/update Markdown vault notes for sessions, decisions, and handoffs.
5. `builder prompt-eval` — run promptfoo evals for lane guides/personas.
6. `builder semantic` — read-only Serena symbol/reference mapping.
